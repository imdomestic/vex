# 执行指令：ruri R2 —— GitHub 登录、PR 预览、基于 mrpack 的模组同步

- 日期：2026-10-18
- 仓库：`imdomestic/ruri-chorus`，在 `feat/vex-experimental` 上继续开发
- 依赖：vex P2，具体是第 5、7、9 节的服务端接口。每一项都要等对应的服务端接口上线后，才能做真实联测，不要用 mock 代替。
- 沿用 R1 的全部规则：上游约定、开关关闭时与上游保持一致、不对外联系上游。
- 本轮的指令和报告放在 vex 仓库的 `docs/ruri/` 下，不再提交到 ruri 分支。

## 1. GitHub 登录

服务器的 `auth.methods` 中包含 `github` 时，登录弹窗显示「使用 GitHub 登录」，流程如下：

1. 调用 `POST /v2/auth/device`。
2. 弹窗显示用户码（字号加大，带复制按钮）、「打开 GitHub」按钮和"等待授权…"；按 `interval` 轮询 `/v2/auth/device/poll`。
3. 用户可以随时取消。取消后停止轮询。
4. 错误时显示以下提示：
   - `expired_token`：「授权已超时，请重新登录」
   - `access_denied`：「已在 GitHub 上拒绝授权」
   - `account_not_linked`：「这个 GitHub 账号尚未加入该服务器，请联系管理员」

CLI 新增 `ruri vex login --github`：打印用户码和网址，等待授权完成。不加 `--json` 时，尝试自动打开浏览器。

## 2. PR 预览

- Git 页在每个项目下新增「Pull Requests」分组，数据来自 `GET …/pulls`。每一项显示编号、标题、作者、是否来自 fork、预览房间的状态和 Build 状态，并提供「进入预览」操作。
- 房间状态为「已休眠」时，进入操作仍然走现有的 start 加租约流程，不依赖连接唤醒。
- CLI：
  - `ruri vex pulls [--server] [--project]`
  - 现有的 `prepare` 和 `launch` 可以接受 `pr<number>-<loader>` 形式的房间 ID。

## 3. 改用 mrpack 同步模组

- 在 `VexModSynchronizing` 接口下新增一个实现，基于房间包 `…/rooms/{id}/pack.mrpack`，复用上游 `RuriCore/Modpacks/MRPack.swift` 的解析和文件安装逻辑。
  - 跳过包里的 `servers.dat`。ruri 使用 QuickPlay，并且已有清理隐藏地址的逻辑。
- 必须保留 R1 的安全行为：
  - 托管文件按哈希校验；
  - 保留非托管文件；
  - 拒绝覆盖用户改动过的托管文件；
  - 发生冲突时直接报错。
- 先判断上游的整合包更新逻辑能否满足这些要求：
  - 能满足：直接使用上游逻辑。
  - 不能满足：在报告中逐项列出差距，安装环节继续使用 R1 的 `VexModSync`，只把文件清单的来源换成 mrpack。
- 增加一项判断：实例当前的文件集合已经等于目标 Build 的 `clientFingerprint` 时，跳过同步。
- 两种实现可以通过内部开关切换。验收完成后，删除被替代的那一种。

## 验收

1. 在 GUI 中用 GitHub 登录 encore 成功；取消、超时、账号未关联三种情况的提示正确；CLI 的 `--github` 也能登录成功。
2. Git 页能看到 example 的 PR 及其预览状态；从 GUI 进入 PR 预览服后，游戏内确认运行的是 PR 中的版本。
3. 基于 mrpack 的同步完成后，实例中的模组集合等于 Build 中 `both/client` 文件的集合，三种哈希全部一致，非托管文件保留；指纹一致时确实跳过同步。
4. 开关关闭时：
   - CLI golden 与上游逐字节相同；
   - Vex 专属目录以外的接入文件仍不超过 15 个，新增的接入点在报告中说明理由。
5. 报告写在 vex 仓库 `docs/ruri/reports/<日期>-ruri-vex-r2.md`。
