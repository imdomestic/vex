## 配置和接口决定

- P1 的 MC 版本与 Java 版本放在 `projects.<p>.minecraft`，供每个项目的宿主构建和服务端镜像选择使用。P2 的仓库清单尚未进入本轮实现范围。
- 平台 agent 目录使用 `agents.<id>`，条目记录 Minecraft、loader、版本和文件路径；项目 loader 的 `agent` 字段引用该条目。这样同一个 Java 版本可以对应不同 MC 和 loader 的 agent。
- 内部管理器使用 `Config.ForProject` 生成的项目配置上下文，TOML 接受新的项目配置结构。
- 记录主键与计数器由共享 SQLite 连接的项目作用域处理；SSE 的首次 sync 使用同一个只读事务读取订阅范围内的对象。
- `/v2/projects` 返回项目数组，字段包括 `id`、`remote`、`defaultBranch`、`role`、`minecraft`、`java`、`loaders`、`policy`、`quota`。各房间、构建、提交、分支、世界和归档对象包含 `project`。
- SSE 的单项目 sync 包含该项目 ID；全局 sync 包含 `projects` 数组，其对象逐个携带 `project`。事件保持完整对象载荷，ready 和 failed 也携带项目。
