# 2026-10-18 Vex P1 登录与会话验收

## 配置与接口

实现采用 [登录补充指令](../directives/2026-10-18-vex-p1-login.md) 和 [API v2 契约](../api.md)。服务版本为 `0.3.0`。

- 会话使用 32 字节随机数，数据库保存 SHA256，以及用户、客户端、创建时间、最近使用时间和到期时间。默认 `auth.session_ttl = "2160h"`，认证成功后顺延；会话可以单独吊销。
- 邀请使用 8 位 Crockford base32，只保存摘要，默认 `auth.invite_ttl = "24h"`。兑换与会话写入在一个 SQLite 事务内完成；在取得事务并读取记录后核验到期时间。
- `GET /i/{code}` 返回固定说明页，预取不会校验或消费邀请。公开兑换正文的读取期限为 10 秒，来源 IP 和整个服务分别限速。
- Unix 管理入口默认 `/run/vex/admin.sock`，权限为 `0660`，属组 `vex-admin`。监听前检查父目录所有者和访问权限。Nix 模块通过 `services.vexd.adminUsers` 登记管理组成员。
- admin 可以为用户创建邀请；新身份不会自动获得 admin 或项目角色。`vexd user invite`、`vexd user sessions --revoke` 使用 Unix 管理入口。
- CLI 通过 `[servers.<name>]`、`default_server` 和 `--server` 管理多个服务器。每个规范化 URL 使用独立凭据；自动化保留静态 `token_sha256`，支持 `login --token-stdin` 和 `token_file`。
- macOS 使用 Keychain。Linux 使用 libsecret 的 `secret-tool`，调用期限为 10 秒；系统凭据服务不可用时保存当前用户独占的 `0600` 文件。Nix 包为 `vex` 提供固定的 libsecret 可执行文件。
- 同一 Kubernetes 集群中的实例配置独立的 `namespace_prefix`、`system_namespace`、数据目录、监听地址、zone 和管理 socket。

## 真实组件与边界检查

`controller/internal/api/login_test.go` 使用真实 HTTP handler、网络连接和 SQLite，覆盖邀请预取、并发兑换只能成功一次、权限边界、会话逐个撤销、滑动到期、实际到期、事务等待跨过有效期、限速和公开 meta。慢正文检查通过真实 TCP 连接发送不完整 JSON，服务在读取期限内返回错误。

`controller/cmd/vex/login_test.go` 同时运行两个独立服务和 SQLite 数据库，两个服务具有相同的项目 ID。检查真实 CLI 命令、服务账号登录、邀请登录、服务器选择、单项目选择、凭据隔离和逐服务器退出。本机实际使用 macOS Keychain；encore 的 SSH 环境实际使用 `0600` 文件。

Linux 测试另外使用固定的 `/nix/store/87a0pwb7dzaiabw8gwqkcinkl8wnr6hr-libsecret-0.21.7/bin/secret-tool`。当前 SSH 环境中的 Secret Service 未提供可用的保存操作，三次调用均在规定期限内结束，文件保存及后续读取、退出检查全部通过，完整测试耗时 30.14 秒。

`controller/cmd/vexd/users_test.go` 使用真实 Unix listener 与管理 handler，检查首次登记身份、会话列举、撤销，以及拒绝对其他用户开放的 socket 父目录。`users_integration_test.go` 在 encore 以实际系统 UID 和组启动子进程，验证 linwhite 与 nobody 的访问结果。测试没有改变系统用户组或用户主目录权限。
