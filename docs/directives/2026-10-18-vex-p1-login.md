# 执行指令补充：vex P1 登录与会话

- 日期：2026-10-18
- 补充对象：`2026-10-17-vex-p0-p1.md` 与 `2026-10-17-vex-p1-amendment.md`
- 设计依据：`docs/design/vex.md` v0.3，第 4、5.3、13、14 节

本补充与前两份指令冲突的地方，以本补充为准。

## 背景

人工使用时不再直接接触 token，客户端只做「登录」：

- P1：用一次性邀请链接登录。
- P2：用 GitHub 登录（device flow）。

配置文件里的 `token_sha256` 保留下来，但只当作服务账号令牌，给自动化和 CI 用。

## 实现内容

### L1 会话

- 所有登录方式成功后，统一签发 vexd 自己的会话 token：
  - 32 字节随机数，DB 中只存 sha256；
  - 记录 user_id、客户端名称（例如 "ruri on Linwhite's Mac"）、创建时间、最近使用时间、到期时间。
- 有效期取 `auth.session_ttl`，每次使用后顺延。会话可以单独吊销。
- 静态令牌和会话 token 都放在 `Authorization: Bearer` 中。服务端按哈希查找，不区分类型。

### L2 邀请

- **创建邀请**：调用 `POST /v2/auth/invites`，请求体为 `{user?, ttl?}`。
  - 普通用户只能给自己创建（用于新设备）；admin 可以给任何用户创建。
  - 响应只返回这一次 `{link, code, expiresAt}`，之后无法再次取回。
  - 链接格式为 `<public_base_url>/i/<code>`。
  - code 是 8 位 Crockford base32，按 `XXXX-XXXX` 分组显示。DB 中只存哈希，邀请只能使用一次，有效期默认取 `auth.invite_ttl`。
- **兑换邀请**：调用 `POST /v2/auth/invites/redeem`，请求体为 `{code, client}`。
  - 成功时返回会话 token 和 `/v2/me` 的内容。
  - 按来源 IP 加全局两级限速。
  - 失败时统一返回 `invite_invalid`，不区分"不存在"和"已过期"。
- **`GET /i/{code}`**：返回一个纯静态说明页，内容为"请在 ruri 的 设置 → 实验性功能 → Vex 服务器 → 添加服务器 中粘贴这个链接，或执行 `vex login <链接>`"。
  - 这个请求不兑换邀请，也不校验 code 是否有效。原因是聊天软件会预取链接，如果在这里兑换，邀请会被预取请求用掉。

### L3 本机管理入口

- **管理 socket**：vexd 监听 `auth.admin_socket`（Unix socket），权限 0660，属组为 `vex-admin`。通过它发来的请求视为 admin。
- **管理命令**：`vexd user invite <name> [--ttl]` 和 `vexd user sessions <name> [--revoke <id>]` 通过 socket 执行，用于新部署时创建第一个用户，以及运维操作。
- **Nix 模块**：创建 `vex-admin` 组。我们的部署中，把 linwhite 加入这个组。

### L4 其他端点与 meta

- `GET /v2/me/sessions`、`DELETE /v2/me/sessions/{id}`、`POST /v2/auth/logout`。
- `GET /v2/meta` 不需要登录即可访问。
  - 未登录时只返回 `{name, version, auth: {methods: ["invite"]}}`，配置了 GitHub 后 `methods` 里会出现 `"github"`。
  - 登录后返回完整内容。
  - `name` 取新增配置项 `server.name`，默认用主机名。

### L5 vex CLI

- 新增命令：
  - `vex login <服务器地址或邀请链接>`。传入邀请链接时自动解析出服务器地址并兑换。
  - `vex login --token-stdin`，用于自动化。
  - `vex logout`、`vex whoami`。
  - `vex user invite <name>`（admin）。
  - `vex auth invite`（给自己的新设备）。
- 支持多个服务器：
  - 用户配置中的服务器写成 `[servers.<name>]`；
  - 全局参数 `--server`，配合 `default_server`；
  - 会话 token 保存在系统钥匙串里（macOS 用 Keychain，Linux 用 Secret Service），不可用时退回到权限为 0600 的文件。

### L6 迁移

迁移后的现有 token 作为服务账号令牌继续有效。linwhite 和 hank 改用邀请登录，旧 token 由用户决定何时从配置中删除。

## 新增验收项（接在之前的编号后面）

15. **邀请登录全流程**：admin 用 `vex user invite hank` 生成链接；hank 在另一台设备上执行 `vex login <链接>` 成功；再用同一个链接兑换一次，返回 `invite_invalid`。
16. **说明页不消耗邀请**：先用 `curl` 访问 `/i/<code>`，再兑换，兑换仍然成功。
17. **吊销**：吊销某个会话后，该 token 立即返回 401；`logout` 之后同样返回 401。
18. **管理 socket 权限**：不在 `vex-admin` 组中的用户无法连接管理 socket。
19. **限速**：同一 IP 连续兑换无效 code 时触发限速，并返回明确的错误码。
20. **meta 无登录访问**：未登录访问 `/v2/meta`，只返回 name、version 和 auth.methods。
